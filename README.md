# PIPEOX

وب‌سایت تأمین لوله، اتصالات، فلنج و شیرآلات صنعتی — فارسی و راست‌چین.

| بخش | فناوری |
|---|---|
| رابط کاربری | Angular 21 با رندر سمت سرور (SSR) برای سئو |
| بک‌اند | NestJS 12 (Node.js) |
| پایگاه داده | MongoDB |

سایت عمومی، حساب مشتری‌ها و پنل مدیریت همه در یک پروژه‌اند و در production با **یک فرمان روی یک پورت** اجرا می‌شوند.

---

## نصب و اجرا

پیش‌نیاز: **Node.js 22.12 یا جدیدتر** و **MongoDB** (روی همین سیستم، یا آدرس MongoDB Atlas).

```bash
npm install          # نصب همه وابستگی‌ها (ریشه، api و web)
npm run setup        # ساخت .env: رمز اولین کاربر پنل (admin)، کلید امنیتی و آدرس پایگاه داده
npm run dev          # حالت توسعه → http://localhost:4200
```

نسخه نهایی:

```bash
npm run build
npm start            # → http://localhost:4000
```

- اولین اجرا محتوای اولیه (پوشه `seed/`) را در پایگاه داده می‌ریزد؛ بعد از آن همه‌چیز از پنل مدیریت ویرایش می‌شود.
- ورود به پنل با نام کاربری و رمز؛ اولین کاربر `admin` است. کاربران و نقش‌ها (مدیر / برنامه‌نویس) از پنل ← «کاربران پنل» مدیریت می‌شوند.
- ساخت کاربر یا بازیابی رمز فراموش‌شده از خط فرمان: `npm run admin:user`
- خروج خودکار: بعد از ۳۰ دقیقه بی‌کاری (مدیر و مشتری).
- تست‌ها (روی یک پایگاه داده آزمایشی جدا): `npm test`

## نشانی‌ها

| آدرس | کاربرد |
|---|---|
| `/` | سایت |
| `/account` | حساب مشتری: ورود، ثبت‌نام، پیگیری استعلام‌ها |
| `/admin` | پنل مدیریت |
| `/sitemap.xml` · `/robots.txt` | خودکار، از روی محصولات و مقالات منتشرشده |

## انتشار روی سرور

1. Node.js و MongoDB را نصب کنید (یا از MongoDB Atlas استفاده کنید).
2. پروژه را کپی کنید و `npm install` ، `npm run setup` و `npm run build` را اجرا کنید.
3. در `.env` مقدار `NODE_ENV=production` و `SITE_URL=https://دامنه-شما` را بگذارید.
4. `npm start` را با یک مدیر سرویس اجرا کنید تا بعد از ری‌استارت سرور هم بالا بیاید (مثلاً systemd یا pm2، یا بخش Node.js پنل هاست).
5. nginx یا پروکسی پنل هاست را برای HTTPS جلوی پورت ۴۰۰۰ بگذارید و `TRUST_PROXY=1` کنید.
6. از پوشه `DATA_DIR` (عکس‌ها و پیوست‌ها) و پایگاه داده نسخه پشتیبان بگیرید.

تنظیمات ایمیل (اعلان استعلام و بازیابی رمز مشتری) و ربات بله/تلگرام در `.env` است؛ راهنمای هر مورد در `.env.example`.

> فایل `.env` پروژه بر متغیرهای سراسری سیستم مقدم است؛ اگر روی سیستم `MONGODB_URI` پروژه دیگری تعریف شده باشد، این سایت به آن دست نمی‌زند.

## ساختار پروژه

```
├─ server.mjs            اجرای production: API و سایت در یک پروسه
├─ scripts/              setup (ساخت .env) · dev (اجرای هم‌زمان api و web)
├─ seed/                 محتوای اولیه (فقط برای پایگاه داده خالی)
├─ design/               طرح تأییدشده صفحه اصلی
├─ api/                  NestJS
│  ├─ src/
│  │  ├─ config/         قرارداد متغیرهای محیطی (اعتبارسنجی با Zod)
│  │  ├─ common/         امنیت (CSRF، هش رمز)، بررسی فایل، پاک‌سازی HTML، CSV
│  │  ├─ database/       بارگذاری محتوای اولیه
│  │  └─ modules/        auth · settings · products · articles · projects ·
│  │                     inquiries · subscribers · media · notifications · seo · dashboard
│  └─ test/              تست‌های end-to-end
└─ web/                  Angular
   ├─ public/assets/     تصاویر، فونت‌ها
   └─ src/
      ├─ styles/         سیستم طراحی (CSS)
      └─ app/
         ├─ core/        سرویس API، سئو، تاریخ شمسی، وضعیت سایت و کاربر
         ├─ shared/      آیکن‌ها، فرم استعلام، کارت‌ها، انیمیشن‌ها
         ├─ layout/      هدر، فوتر، لوگو
         └─ features/    home · products · insights · pages · account · admin
```

## امنیت

- **نشست‌ها:** نشست مشتری و مدیر در کوکی httpOnly و SameSite است.
  - با تغییر رمز، نشست‌های دیگر باطل می‌شوند.
- **CSRF:** هر درخواست تغییردهنده باید هدر اختصاصی داشته باشد، و Origin آن بررسی می‌شود.
- **محدودیت تلاش:** برای ورود، ثبت‌نام، فرم‌ها و رمز پنل.
- **کپچای تصویری داخلی:** روی ورود، ثبت‌نام، بازیابی رمز، استعلام و خبرنامه (بدون سرویس خارجی؛ هر کد یک‌بارمصرف و ۱۰ دقیقه معتبر).
- **نشست با زمان بی‌کاری:** نشست‌ها بعد از ۳۰ دقیقه بی‌کاری تمام می‌شوند؛ با هر فعالیت تمدید می‌شوند.
- **نقش‌ها:** «مدیر» همه بخش‌ها؛ «برنامه‌نویس» به‌علاوه صفحه «سیستم». تغییر نقش یا غیرفعال‌سازی، نشست آن کاربر را می‌بندد.
- **ورودی‌ها:**
  - همه ورودی‌ها با Zod اعتبارسنجی می‌شوند.
  - کوئری‌های MongoDB در برابر تزریق عملگر (`$gt`, …) محافظت شده‌اند.
- **فایل‌ها:**
  - نوع فایل از روی محتوای آن بررسی می‌شود، نه نام آن.
  - فایل‌ها بیرون از پوشه برنامه و با نام تصادفی ذخیره می‌شوند.
- **مقالات:** متن مقالات هنگام ذخیره با فهرست مجاز پاک‌سازی می‌شود.
- **هدرهای امنیتی:**
  - Content-Security-Policy سخت‌گیرانه با nonce جداگانه برای هر درخواست
  - هدرهای helmet
  - محدودیت نام میزبان (`NG_ALLOWED_HOSTS`) در SSR
